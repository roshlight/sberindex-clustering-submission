# Воспроизведение независимого аудита

Переносимые скрипты находятся в `scripts/enriched_audit/`. Они читают данные из явно заданного `--repo`, сохраняют новые проверки в `--out` и не вызывают внешний поиск или модельные API. Аналитический код, исходные таблицы и опубликованные манифесты не изменяются. Скрипты отказываются записывать результат внутрь `reports/`, `src/`, `configs/` и `data/` репозитория.

Нужны Python и зависимости из корневого `uv.lock`, исходный `data/raw/consumption.parquet`, `reports/initial_study/assignments.parquet`, перечисленные в `audit_manifest.json` таблицы обогащения и завершённый `reports/enriched_analysis/core_v2`. При отсутствии файла проверка завершается ошибкой; загрузки и подстановки источников не выполняются. Исходные архивы следует предварительно распаковать по путям из пакета данных.

Команды выполняются из корня репозитория. `../../work/enriched-analysis/audit-rerun` — отдельный каталог рабочего пространства; его можно заменить собственным путём. Обычный режим Python обязателен: не используйте `-O` или `PYTHONOPTIMIZE`, поскольку часть проверок записана как `assert`.

```powershell
uv run --frozen python -X utf8 scripts/enriched_audit/audit_inputs.py --repo . --out ../../work/enriched-analysis/audit-rerun
uv run --frozen python -X utf8 scripts/enriched_audit/coverage_details.py --repo . --out ../../work/enriched-analysis/audit-rerun
uv run --frozen python -X utf8 scripts/enriched_audit/validate_core.py --repo . --out ../../work/enriched-analysis/audit-rerun
```

Первый скрипт восстанавливает условные маски и диагностические таблицы, второй — покрытие по регионам и типам, третий — сверяет завершённый аналитический прогон. Параметр `--audit` у двух последних скриптов позволяет указать отдельный каталог входного аудита; по умолчанию это `--out`. `--core` у третьего скрипта позволяет явно выбрать каталог проверяемого прогона; по умолчанию используется `reports/enriched_analysis/core_v2` внутри `--repo`.

Третий скрипт не импортирует функции `municipal_profiles.enriched_analysis`. Он заново строит годовые цели из 12 месячных исходных профилей, сверяет принятые источники и маски, пересчитывает все OOF-метрики, восстанавливает все ridge-прогнозы прямым матричным решением и проверяет OLS через SVD. Bootstrap повторно рассчитывается по сохранённым прогнозам, без переобучения моделей; отдельно проверяется отсутствие пересечения регионов в `heldout_regions`.

Ожидаемый итог текущего снимка: `PASS_conditional_join_audit`, затем `PASS_with_interpretation_conditions`; 4 032 годовые строки, 2 016 ID, 60 690 OOF-строк, 68 строк метрик, 40 сравнений, 15 коэффициентов OLS, 1 891 стабильная пара и 48 именованных проверок. Подробности — в новом `core_validation.json`; разбиения и покрытие — в `core_validation_folds.csv` и `core_validation_coverage.csv`.

Переносимая версия проверена на отдельном scratch-каталоге. Табличные результаты входного аудита должны совпасть с опубликованными; время формирования, относительное представление путей и хеш самого перенесённого скрипта закономерно отличаются. Старые `audit_manifest.json` и `core_validation.json` сохраняют происхождение первоначальной проверки и не переписываются новым запуском.

Проверка стиля затрагивает только эти скрипты:

```powershell
uv run --frozen ruff check scripts/enriched_audit
uv run --frozen ruff format --check scripts/enriched_audit
```
