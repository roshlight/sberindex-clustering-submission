# Воспроизведение четвёртого раунда

Статус поставки: **ready for independent reproduction**. Компоненты и независимые проверки выполнены в существующем окружении Windows. Отдельный получатель ещё не повторял весь путь в новом окружении; это не заявляется как завершённое независимое воспроизведение с нуля. Сетевые источники и ответы модели изменчивы, поэтому воспроизводится сохранённый снимок.

Владелец поставки: команда репозитория `sberindex-hackathon-2026/municipal-economic-profiles`; ответственному за следующий анализ нужно сохранить ограничения этого документа. Дата: 16.09.2026. Исходный коммит перед сбором: `5c6edb40636fad1cbaa4fbcbc041169dfe80e11f`. Код поставки фиксируется тегом `data-round4-2026-09-16`; содержимое нового пакета перечислено в [delivery_manifest.json](delivery_manifest.json).

## Контракт результата

Пакет отвечает на вопрос, какие новые данные удалось получить после третьего анализа и какие из них сопоставимы с нашей панелью 2016 МО за 2023/2024 годы. Основной результат: 779 дополнительных числовых ячеек БДПМО в отдельном кандидате. МСП, документальные примеры и география имеют ограничения, описанные в [отчёте](REPORT.md).

Канонические результаты находятся в `reports/data_round4/`. Сырые источники лежат только в пяти архивах релиза; временные `replay-*` не являются новыми каноническими версиями. Старые панели и модельные отчёты не заменяются. Причинные объяснения, качество нового алгоритма и готовый муниципальный признак МСП не входят в подтверждённые результаты.

## Получение и проверка пакета

Нужен доступ к частному GitHub-репозиторию через `gh`, принадлежащий участнику команды. Для воспроизведения сохранённых данных не нужны Telegram, серверные ключи, SearXNG или OpenRouter. Потребуются Python 3.12, `uv`, Windows PowerShell и примерно 5 ГБ свободного места для архивов, извлечённых файлов и результатов. Для SQL-аудита используется 2 потока, лимит памяти DuckDB 2 ГБ; желательно 8 ГБ ОЗУ. GPU не нужен. Платных API-вызовов при replay нет.

В новом пустом рабочем каталоге:

```powershell
New-Item -ItemType Directory outputs
gh repo clone sberindex-hackathon-2026/municipal-economic-profiles outputs/municipal-economic-profiles
Set-Location outputs/municipal-economic-profiles
git switch --detach data-round4-2026-09-16
uv sync --project enrichment --frozen
New-Item -ItemType Directory -Force ../../work/data-round4/release
gh release download data-round4-2026-09-16 --pattern '*.zip' --pattern SHA256SUMS.txt --dir ../../work/data-round4/release
$assetRoot = (Resolve-Path ../../work/data-round4/release).Path
Get-Content (Join-Path $assetRoot SHA256SUMS.txt) | ForEach-Object {
    $parts = $_ -split '\s+', 2
    $assetPath = Join-Path $assetRoot $parts[1]
    if ((Get-FileHash -LiteralPath $assetPath -Algorithm SHA256).Hash.ToLowerInvariant() -ne $parts[0]) {
        throw "Archive checksum mismatch: $($parts[1])"
    }
}
Get-ChildItem -LiteralPath $assetRoot -Filter '*.zip' | ForEach-Object {
    Expand-Archive -LiteralPath $_.FullName -DestinationPath ../..
}
```

Архивы содержат префикс `work/data-round4/...`: не убирайте его. В каждом ZIP есть `MANIFEST.data-round4-<group>.json`. SHA-256 и размеры архивов также находятся в `delivery/data-round4-*.qa.json`. Для больших источников МСП внутри общего ZIP сохранены именно оригинальные ZIP поставщика; отдельный шаг извлекает их без изменения журналов получения.

## Единая команда проверки

Из корня репозитория:

```powershell
uv run --project enrichment --frozen python enrichment/scripts/replay_round4.py --repo . --raw ../../work/data-round4 --output ../../work/data-round4/replay-independent
```

Каталог результата должен быть новым. Команда выполняет пять ветвей, независимые проверки экономики и МСП, сравнивает результаты с каноническими файлами и сохраняет журналы каждого шага. `QA.json` создаётся только после всех успешных шагов; `stages.json` фиксирует пройденные этапы даже при остановке. Несовпавший хеш, отсутствующий источник, недопустимый ключ или ошибка шага останавливают работу.

`extract_round4_sme.py` создаёт только отсутствующие распакованные Parquet. Он сверяет оригинальные архивы и элементы с сохранёнными метаданными, читает CRC, проверяет безопасные пути и не заменяет отличающийся существующий файл. `collect_round4_sme.py --recover` здесь не используется: это режим восстановления скачивания, который создаёт новые метаданные получения.

Кейсы воспроизводятся из явно сохранённого ручного рецепта. Проверка подтверждает байты PDF и ранее просмотренных изображений, но не заменяет новое визуальное чтение человеком. Оценка законов и сносок также остаётся содержательной частью аудита. Оригиналы и локаторы страниц включены в архивы.

## Окружение и качество

Зависимости зафиксированы в `enrichment/uv.lock`. Запуски сделаны на Windows, Python 3.12; машинная версия окружения записана в `QA.json`. Веб-сбор на сервере выполнялся отдельно; его код и зависимости сохранены в `implementation_snapshot` внутри архива поиска. Числовой replay использует только локальные файлы. Случайного обучения или случайных выборок в этом раунде нет.

```powershell
uv run --project enrichment --frozen pytest enrichment/tests -q
uv run --project enrichment --frozen ruff check enrichment
uv run --project enrichment --frozen ruff format --check enrichment
```

| Этап | Статус доказательства |
|---|---|
| Получение исходников | Выполнено; неуспешные запросы сохранены отдельно |
| Проверка сырых байтов | SHA-256 каждого опубликованного файла, чтение ZIP с CRC |
| Пересборка и сравнение | Локальный replay; журнал в `delivery/replay_QA.json` |
| Независимый числовой аудит | Экономика и МСП отдельными проверяющими без импорта расчётных функций |
| Новое чистое окружение получателя | NOT RUN |
| Обучение и оценка моделей | NOT IN SCOPE |
| Повторный поиск с теми же результатами | Не гарантируется; выдача и источники изменяются |

Автоматический поиск через сервер получил нулевую выдачу из-за ограничений движков; прямой сбор и дополнительный веб-поиск дали исходники. Пять карточек DeepSeek V4 Pro не являются числовыми данными. Межисточниковая проверка модели завершилась ошибкой; журнал и стоимость сохранены в [search/README.md](search/README.md).

## Обновления и передача

Для новой сетевой версии используйте новый каталог кэша и результата, затем повторите аудит единиц, охвата, годов, кодов и географии. Отличие от старого хеша означает новую версию источника, а не повод заменить ожидаемый хеш в опубликованном отчёте. Архивы и прежние результаты сохраняются для сравнения.

Географические ограничения и отсутствие данных МСП не снимаются успешным запуском кода. Источники нужны для описания структуры территорий; суммы не устанавливают доход жителей, причинность или полноценную занятость. Вопросы об экономической интерпретации и следующем эксперименте обсуждаются с командой в существующем репозитории и чате. Внешние запросы из `geography/missing_requests.csv` пока только подготовлены.

Общие исходники МСП содержат открытые регистрационные записи поставщика. В отчётах публикуются агрегаты качества; персональные профили не строились. Лицензии и атрибуция приведены в предметных README и заметке релиза. Доступ к релизу соответствует частному репозиторию команды.
