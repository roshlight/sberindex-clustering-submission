# Географическая сопоставимость: четыре приоритетных МО

На 16 сентября 2026 года подтверждена **идентичность геометрии, поставленной СберИндексом для годовых выборок 2023 и 2024**, для Беломорского, Питкярантского, Сегежского и Великоустюгского МО. Независимая сопоставимость их юридических границ остается **unknown**: парные датированные координатные наборы из официального реестра не получены. Исключения для 78 преобразований и календарные ограничения, включая городской код Великого Устюга за 2023 год, не изменены.

## Что удалось установить

В исходном GeoPackage СберИндекса для каждого из четырех ID есть одна выбранная геометрическая запись с интервалом `2018 <= year < 9999`. При выборе 2023 и 2024 годов совпадают сами BLOB-байты, а не только название или код. Полные SHA-256, исходные `fid`, `osm_ref`, `osm_vers` и интервалы находятся в [publisher_annual_versions.csv](publisher_annual_versions.csv). [publisher_geometry_identity.csv](publisher_geometry_identity.csv) содержит четыре сравнения.

| territory_id | МО | ОКТМО Сбер, 2023 | ОКТМО Сбер, 2024 | Геометрия в поставке |
|---|---|---|---|---|
| 208 | Беломорский | 86-604-000-000 | 86-504-000-000 | Одинаковые байты |
| 217 | Питкярантский | 86-633-000-000 | 86-533-000-000 | Одинаковые байты |
| 221 | Сегежский | 86-645-000-000 | 86-545-000-000 | Одинаковые байты |
| 1051 | Великоустюгский | 19-514-000-000 | 19-514-000-000 | Одинаковые байты |

Свежая загрузка [метаданных СберИндекса](https://www.sberbank.ru/common/img/uploaded/files/pdf/sberindex/metadata_municipal_dict_sberindex_2.pdf) дала тот же SHA-256, что и ранее сохраненный файл. Документ заявляет покрытие по **01.01.2024**, годовые версии и учет внутригодовых изменений к началу следующего года. Источник полигонов — OSM; поставщик описывает ручные корректировки для согласования соседних территорий разных версий и полного покрытия страны. Это позволяет воспроизвести выбор геометрии, но не проверить корректность каждой ручной правки или привязку показателей Росстата к постоянным границам.

Поле `osm_vers` у всех четырех записей содержит литерал `2023-01-01T01:00:00Z`. Он сохранен без переинтерпретации. Метка `gpkg_contents.last_change = 2024-10-17T12:11:38.270Z` — метаданные файла; она не принята за дату действия юридической границы. Начало интервала 2018 также не доказывает наличие независимого наблюдения геометрии за каждый год.

## Новые файлы и повторно использованные источники

Реестр содержит 15 записей: 14 доступных источников и одну неуспешную попытку скачивания. Из доступных файлов **6 впервые получены в этом раунде**, один заново скачан с прежними байтами, 7 скопированы из предыдущих поставок с проверкой SHA. Результаты и ограничения каждой записи приведены в [source_ledger.csv](source_ledger.csv).

- С [официального раздела градостроительства Питкяранты](https://xn--80ayif.xn--p1ai/gradostroitelstvo.html) получены текущая страница, материалы обоснования генплана — 64 страницы, **2025 год** на титуле, — и карта функциональных зон. Это планировочные материалы более позднего периода; их нельзя принимать за внешнюю границу на 01.01.2023 или 01.01.2024. Титул и карта визуально проверены. В составе генплана отдельно названа карта границ округа и существующих населенных пунктов: это точный дополнительный файл для запроса администрации.
- Получен официальный устав Питкярантского района в редакции 25.09.2019 № 208, 54 страницы. Статья 2 отсылает к 825-ЗРК от 01.12.2004. Устав подтверждает прежний статус, но не заменяет полный комплект граничных приложений в редакции перед преобразованием.
- [Сообщение Росреестра на сайте администрации Ведлозерского поселения](https://vedlozero.ru/poselenie/news/novosti-upravleniya-rosreestra-po-respublike-kareliya-12), опубликованное 23.12.2024, сообщает о границах 491 из 845 **населенных пунктов** в ЕГРН на 01.12.2024. Это республиканский контекст, не число МО и не свидетельство отсутствия границы любого из четырех рассматриваемых муниципалитетов.
- [Документ Иркутского парламента](https://eparlament.irzs.ru/Files/getFile/56041) — пояснительная записка с упоминанием закона 2025 года и цитатой из письма Росреестра от 06.06.2024 № 13-5187-АБ/24. Он сохранен как официальный контекст требований к описанию границ. Это **не оригинал письма** и не доказательство для четырех МО; дата в локальном имени файла относится к цитируемому письму.

Пять законов из раунда 3 повторно включены с прежними SHA: 2837-, 2838-, 2839-, 2841-ЗРК и 5115-ОЗ. Закон 2841-ЗРК содержит официальные описания и схемы границ после преобразования. Парного координатного представления старых районов нет. Для Великоустюгского МО закон 5115-ОЗ указывает административный состав и отменяет 1109-ОЗ от 06.12.2004. Приложение с 412 населенными пунктами использует ОКАТО; его нельзя подменять городскими кодами ОКТМО.

## Что требуется дальше

[missing_requests.csv](missing_requests.csv) содержит пять конкретных запросов, которые **не отправлялись**. Для трех карельских МО нужны координатные описания внешней границы района на 01.01.2023 и округа на 01.01.2024, реестровые номера, CRS, даты действия и основания изменения. Для Великоустюгского МО дополнительно нужен 1109-ОЗ с приложениями в редакции на 31.05.2022, а календарное действие городского `19514000001` требует отдельного подтверждения. У СберИндекса нужны журнал ручных правок и правило переноса статистических строк в постоянные границы.

Пространственное пересечение, площадь расхождения и overlap в этом пакете **не вычислялись**. Равенство поставленных байтов не дает независимой проверки источника этих же байтов. Текущий OSM, сходство названий и кодовая преемственность населенных пунктов не использованы для снятия ограничений.

## Файлы и воспроизведение

`evidence.csv` содержит 14 свидетельств с локатором, URL, SHA, назначением и ограничением. В `geometry/` сохранены четыре точные копии бинарного поля GeoPackage. Формат `.gpkgblob` включает заголовок GeoPackage: **это не самостоятельный файл WKB**. Исходный полный GPKG находится в сырьевом архиве.

В архив релиза нужно включить ровно 34 файла из [raw_inventory.json](raw_inventory.json), всего **89 029 173 байта**, с корнем `work/data-round4/geography/` относительно общего workspace. Там есть исходные PDF/HTML, повторно использованные GPKG/XLSX/законы, журналы получения, проверенные постановки свидетельств, извлеченный текст и три изображения для визуальной проверки. Служебных окружений, ключей и OCR-runtime нет.

После распаковки архива сохраните структуру workspace. Из `outputs/municipal-economic-profiles/enrichment`:

```powershell
uv run --frozen python scripts/collect_round4_geography.py --raw-root ../../../work/data-round4/geography --output ../reports/data_round4/geography --verify-only
uv run --frozen pytest tests/test_round4_geography.py -q
uv run --frozen ruff check scripts/collect_round4_geography.py tests/test_round4_geography.py
uv run --frozen ruff format --check scripts/collect_round4_geography.py tests/test_round4_geography.py
```

Для новой сборки уберите `--verify-only` и задайте **новый, несуществующий** каталог вывода. Replay работает без сети: проверяет входные SHA, заново выбирает обе версии в SQLite/XLSX и побайтово сверяет все генерируемые результаты. Он не воспроизводит состояние внешних сайтов и не автоматизирует юридическую оценку документов. `manifest.json` относится к машинным результатам; README и QA.md поясняют их границы применимости.
