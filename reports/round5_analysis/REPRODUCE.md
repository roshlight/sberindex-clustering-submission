# Воспроизведение пятого анализа

Проверки `verify_*_bundle.py` сверяют исходные тексты документов. Выполняйте их в [копии с первоначальной документацией](../../submission/REPRODUCE.md#проверка-исторических-контрольных-сумм); расчётные команды и данные от редакционных изменений не зависят.

Статус: **ready for independent reproduction**. Полная вычислительная цепочка повторена в новом каталоге с существующим окружением; независимый проверяющий скрипт прошёл и на опубликованных, и на свежих результатах. Новый независимый запуск с созданием чистого окружения ещё не выполнен. Проверка HTML проведена отдельно штатным браузерным валидатором.

Владелец исследования — команда `sberindex-hackathon-2026/municipal-economic-profiles`. Область применения: ретроспективное описание муниципальных потребительских профилей в первом кейсе, 2023/2024 годы. Базовый коммит до анализа — `932afe503e11d248f39360c6f8f23df75d7819cc`. Код и результаты анализа публикуются последующим коммитом; сохраните его через `git rev-parse HEAD`. Тег `data-round5-2026-09-16` содержит сбор данных, но ещё не содержит этот анализ.

Канонические результаты находятся в `reports/round5_analysis/`, протокол — в `configs/round5_analysis_v1.json`. Старые раунды не заменяются. `artifact.json` хранит блоки и таблицы отчёта; `report.html` — автономный интерактивный файл; `REPORT.md` — представление для GitHub. Все три относятся к одному отчёту.

## Контракт результата

Вопрос: изменили ли 64 новых наблюдения решение о денежном блоке и что уточняют новые источники МСП и инвестиционных объектов? Основной вывод ограничен прежней линейной моделью и фиксированными выборками; новые кластеры не строились. Это не прогноз будущего, оценка причинного влияния, доход жителей или доказательство исторической сопоставимости границ.

Основная цель — MSE по пяти CLR-координатам профиля расходов, равный вес МО. Основная выборка: 1975 / 1998 МО; консервативная: 1897 / 1930. Полная сетка: 4032 пары «МО–год». Порог принятия задан до новых модельных результатов: выигрыш не менее 1% в каждом из двух годов и режимов, положительная нижняя граница интервала, отсутствие разворота на стабильных кодах. Критерий не выполнен.

Вычисления сохраняют старые значения, ключи, знаменатели, выборки и разбиения. Пропуски не принимаются за нули. Доступность числа в 2026 году не доказывает доступность в исторический момент. Годовые строки МСП не приравниваются к численности субъектов в реестре на дату, работники по повторным состояниям ИНН не суммируются.

## Окружение и проверка опубликованного пакета

Использованы Windows, Python 3.12.10 и корневой `uv.lock`; CPU, без GPU и платных API. Контекстный DuckDB использует 2 потока и лимит памяти 2 ГБ. Для распаковки прежних источников МСП и свежего повтора ориентируйтесь на 6 ГБ свободного места и 8 ГБ ОЗУ. GitHub-доступ нужен только для получения репозитория и архивов; OpenRouter, SearXNG, Telegram и серверные ключи для анализа не нужны.

Из корня полученного репозитория:

```powershell
uv sync --python 3.12.10 --frozen
uv run --frozen python scripts/verify_round5_bundle.py --repo .
uv run --frozen python scripts/verify_round5_analysis.py --repo . --out ../../work/round5-independent-check.json
```

Первая проверка сверяет состав поставки, хеши, протокол, происхождение и актуальность заключений. Вторая заново рассчитывает признаки, ошибки, интервалы, разложения и 100 независимых Ridge-моделей; она не скачивает источники и не подменяет содержательный аудит первоисточников.

## Получение полных исходников МСП

Если проверенный каталог `../../work/data-round4/sme/` уже существует, повторная загрузка не нужна. Иначе используйте новый каталог:

```powershell
New-Item -ItemType Directory -Force ../../work/round5-analysis-assets
gh release download data-round4-2026-09-16 --repo roshlight/sberindex-clustering-submission --pattern data-round4-sme.zip --pattern SHA256SUMS.txt --dir ../../work/round5-analysis-assets
$assetRoot = (Resolve-Path ../../work/round5-analysis-assets).Path
$checksumLine = @(Get-Content (Join-Path $assetRoot SHA256SUMS.txt) | Where-Object { $_ -match '\sdata-round4-sme\.zip$' })
if ($checksumLine.Count -ne 1) { throw 'Expected one SME archive checksum' }
$expectedHash = ($checksumLine[0] -split '\s+', 2)[0]
$archivePath = Join-Path $assetRoot data-round4-sme.zip
if ((Get-FileHash -LiteralPath $archivePath -Algorithm SHA256).Hash.ToLowerInvariant() -ne $expectedHash) { throw 'Archive checksum mismatch' }
Expand-Archive -LiteralPath $archivePath -DestinationPath ../..
uv sync --project enrichment --python 3.12.10 --frozen
uv run --project enrichment --frozen python enrichment/scripts/extract_round4_sme.py --raw ../../work/data-round4/sme
```

ZIP имеет префикс `work/data-round4/sme/`; не убирайте его. Экстрактор сверяет исходные ZIP, CRC и SHA элементов, проверяет пути, извлекает только отсутствующие файлы и не меняет журналы получения. Источник — ФНС в обработке «Если быть точным», `v20260605`; происхождение и ограничения сохранены в `reports/data_round4/sme/` и `reports/data_round5/sme/`.

Для модельной части и отчёта все необходимые входы уже находятся в репозитории. Архивы пятого сбора нужны для повторного чтения первоисточников, но не для этой сохранённой вычислительной цепочки; инструкция их получения находится в [описании сбора](../data_round5/REPRODUCE.md).

## Единая команда полного вычислительного повтора

```powershell
uv run --frozen python scripts/replay_round5_analysis.py --repo . --sme-raw ../../work/data-round4/sme --out ../../work/round5-independent-replay
```

Выходной каталог должен быть новым, вне репозитория и каталога сырья. Команда последовательно создаёт свежие `audit`, `models`, `readout`, `recovered`, `context`, затем запускает независимый валидатор именно на свежих результатах. Модели получают свежий `audit` через `--audit-root`; последующие этапы получают новую корневую папку. Никакой подмены повторного расчёта чтением опубликованного выхода нет.

При текущем повторе 22 файла аудита, 5 описательных файлов и 13 файлов контекста совпали побайтно. Прогнозы, метрики и разложения также совпали точно. Код допускает `atol=1e-9`, `rtol=1e-9` для соответствующих числовых таблиц, сохраняя точные ключи и флаги. Временные метки запусков и манифесты с перенаправленными путями не обязаны совпадать побайтно. Предобработка сверяется по структуре и числам. Результаты — в [replay_QA.json](replay_QA.json).

Независимый проверяющий скрипт допускает менее `1e-8` для Ridge и ошибок срезов, менее `1e-10` для остальных проверяемых модельных числовых групп; для CSV-повтора прежних вещественных признаков — `rtol=1e-14`. При проверке описательных таблиц восстановленных МО используются отдельные допуски `atol=1e-8` и относительные допуски `rtol=1e-12` / `rtol=1e-14`, заданные в скрипте. Ключи, маски, прежние исходные числа и реквизиты сравниваются точно. Первый остановленный аудит с излишне строгим сравнением CSV сохранён в `independent_data_QA_attempt01.json`; ожидаемые исходные значения не переписывались.

Ручные README и смысловые заключения не генерируются заново вычислительным повтором. Модельная проверка не повторяет визуальное чтение PDF и аудит трактовки источников; это отдельная граница свидетельств.

## Пересборка отчёта и проверки кода

Отчёт можно пересобрать из свежих результатов в новом каталоге:

```powershell
uv run --frozen python scripts/build_round5_report.py --repo . --root ../../work/round5-independent-replay --out ../../work/round5-independent-report
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
```

Пересборка создаёт четыре расчётных файла отчёта, но не ручные документы. Для самостоятельной передачи новой папки скопируйте в неё канонические `REPRODUCE.md`, `independent_review.md` и `context/README.md` с сохранением вложенности: на них ссылается отчёт. Полный комплект проверочных файлов остаётся в канонической поставке.

HTML создаёт установленный Data Analytics 0.2.10 с нативными графиками и таблицами; это отдельная зависимость сборки, не часть Python lock. Для чтения готового HTML плагин не нужен. Сборка проверена на Node.js 22.23.2 и требует уже установленный Chromium headless-shell: штатный инструмент браузер не скачивает. Если браузер не обнаружен автоматически, задайте `CHROMIUM_EXECUTABLE_PATH` полным путём к его исполняемому файлу либо `PLAYWRIGHT_BROWSERS_PATH` корнем имеющегося кеша браузеров. Укажите фактический корень установленного плагина вместо `<DATA_ANALYTICS_PLUGIN>`:

```powershell
node scripts/build_round2_portable.mjs --plugin <DATA_ANALYTICS_PLUGIN> --input ../../work/round5-independent-report/artifact.json --output ../../work/round5-independent-report/report.html --receipt ../../work/round5-independent-report/portable_delivery.json --work-dir ../../work/round5-independent-native
```

Сохранённый wrapper вызывает штатные упаковщик, извлечение SVG и браузерный валидатор. При известном переполнении заголовка из-за полосы прокрутки Windows он применяет только прежнюю проверенную CSS-поправку ширины; payload и runtime не меняются. Итоговая проверка подтверждает 30 блоков, 4 графика, 11 таблиц, ширины 1440/390 px, доступ к источникам и отсутствие внешних запросов. Она не сертифицирует все браузеры, печать и устройства. Хеши сборщика и runtime записаны в [portable_delivery.json](portable_delivery.json).

## Передача и обновление

Численные утверждения сверяются отдельным `verify_round5_report_claims.py`; содержательные ограничения прошли отдельный просмотр. При новой версии сохраняйте старые результаты и фиксируйте новый вопрос до повторных модельных результатов. Не заменяйте эталонные хеши новой сборкой только ради прохождения проверки. Несовпадение ключей, исходного SHA, схемы или допустимой погрешности требует разбора.

Задачи владельцев источников остаются открытыми: год и происхождение работников, исторические адреса и муниципальные соответствия, фактические затраты по объектам Черского. Внешние запросы не отправлялись. Решение о будущем использовании признаков принимает команда; этот раунд сохраняет денежный блок как контекст и не разрешает историческое муниципальное присоединение МСП.
