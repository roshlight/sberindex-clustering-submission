# Словарь данных обогащения населения

Показатель БДПМО `8112027`: оценка численности населения на 1 января текущего года, единица `persons` (человек). В поставке используются только даты `2023-01-01`, `2024-01-01` и типы `11` (всё население), `12` (городское население). Подписи типов читаются из соответствующей официальной формы; например, «Все» и «Все население» сохраняются в исходном виде.

## Зерно и допустимые соединения

| Слой | Одна строка | Уникальный ключ |
|---|---|---|
| `population_source/population_source.csv` и `.parquet` | Вернувшаяся и принятая ячейка исходного кода | `source_region_url`, `source_oktmo`, `reference_date`, `population_type` |
| `population_source/target_status.csv` | Итог обработки одной цели | `region_url`, `source_oktmo` |
| `population_source/target_reference_links.csv` | Связь годового среза СберИндекса с исходным кодом | `territory_id`, `reference_date`; исходный ключ также должен однозначно связываться с годовым муниципалитетом |
| `population_source/cell_coverage.csv` | Ожидаемая комбинация даты и типа для каждой цели | `source_region_url`, `source_oktmo`, `reference_date`, `population_type` |
| `population/municipal_population.csv` и `.parquet` | Муниципалитет основной панели × дата × тип населения, включая пробелы | `territory_id`, `reference_date`, `population_type` |
| `population/municipal_population_wide.csv` и `.parquet` | Муниципалитет основной панели × дата | `territory_id`, `reference_date` |

Тип `source_oktmo` хранится строкой в числовом представлении самой формы БДПМО. `official_oktmo_8` хранит ровно 8 цифр с ведущими нулями, `sber_oktmo_11` хранит 11 цифр из годовой версии справочника. Их связь опирается на сохранённые официальные записи классификатора и проверенное членство кода в форме. Подобие чисел само по себе не является разрешением обрезать код, дополнять его нулями или переносить население. Муниципальные и региональные названия не используются для нечёткого соединения.

## Поля источника

| Поле | Смысл |
|---|---|
| `source_region_url` | Точный региональный endpoint БДПМО; часть ключа. Номер `munst` нельзя автоматически трактовать как современный код субъекта: например, `munst33` относится к Кировской области. |
| `source_oktmo` | Буквальное кодовое значение `p_oktmo`, выбранное в официальной форме и переданное в запрос. |
| `source_oktmo_name` | Точная нормализованная по пробелам подпись кода в форме; служит доказательством атрибуции ответа. |
| `reference_date` | Дата состояния населения, а не публикации или скачивания. |
| `population_type`, `population_type_label` | Код `mest` и его буквальная подпись в источнике. |
| `value` | Целое неотрицательное число либо null. Число 0 сохраняется только тогда, когда источник явно возвратил `0` и ответ прошёл QA. |
| `value_raw` | Исходная строка ячейки после нормализации пробелов. Сохраняет знак `-`, многоточие или пустую строку. |
| `value_status` | `observed` для принятого числа; `missing_or_unresolved_source_marker` для явного пустого/неразрешённого маркера. |
| `unit`, `indicator_id` | `persons` и `8112027`; проверяются до соединения. |
| `source_csv_row` | Номер физической строки разобранного CSV, начиная с 1. Перенос в заголовке Москвы не сдвигает этот номер искусственно. |
| `source_section` | Полный логический заголовок соответствующей таблицы. Продолжение заголовка может быть объединено пробелом; значения строк не объединяются. |
| `source_url` | URL обработчика, которому отправлен запрос. |
| `source_sha256` | SHA-256 исходных байтов ответа CSV. |
| `request_key` | SHA-256 канонического описания метода, URL и POST-параметров; связывает строку с `.json` и `.raw` кэша. |
| `options_request_key` | Ключ сохранённого запроса официальной формы, откуда взяты коды и подписи измерений. |
| `retrieved_at` | Фактическое время получения ответа, UTC. Оно не является временем публикации данных. |
| `published_at` | Не установлено, null; дату публикации нельзя выводить из года наблюдения. |
| `territory_id`, `join_status` | В исходном слое `territory_id` пуст, `join_status=source_oktmo_unlinked_to_sber`; привязка появляется только в отдельной панели. |
| `extraction_mode` | `batch_unique_source_label` для пакета с уникальными точными подписями либо `single_source_code` для отдельно запрошенного кода. |

Метаданные кэша сохраняют метод, URL, POST payload, конечный URL, редиректы, HTTP-статус, время получения, число байтов и SHA-256. Повторная загрузка того же запроса сохраняет предыдущую пару метаданных и байтов в `history/`. Наличие числа в сыром ответе не означает его принятие: отклонённые ответы также сохранены для аудита.

## Годовая кодовая связь и календарные решения

| Поле или группа | Смысл |
|---|---|
| `territory_id` | Постоянный идентификатор муниципалитета СберИндекса; состав основной панели фиксируется исследованием. |
| `official_oktmo_8`, `sber_oktmo_11` | Представления кода, подтверждённые официальной записью и соответствующим годовым справочником СберИндекса. |
| `official_code_present`, `sber_annual_code_present` | Проверено наличие точного кода в каждом из двух источников. |
| `sber_year_from`, `sber_year_to_exclusive` | Интервал версии справочника: начало включительно, конец исключительно. |
| `registry_sources`, `registry_vintages`, `registry_DateUtv`, `registry_DateVved` | Происхождение записи классификатора и буквальные даты из него; эти даты не объявляются автоматически датами действия муниципальных границ. |
| `temporal_review_required` | Исходный флаг календарного вопроса в таблице связей. |
| `initial_temporal_review` | Копия исходного флага, сохранённая в готовой панели даже после решения. |
| `calendar_review_cleared` | Для точного ключа приложено принятое доказательство разрешения календарного конфликта. |
| `temporal_review` | Неразрешённый остаточный календарный флаг после применения журнала. |
| `calendar_*` | Поля принятого решения: дата допустимого применения, URL, локальный путь к доказательству, SHA-256, локатор и тип захвата. |
| `independent_legal_effectivity_confirmed`, `independent_boundary_equivalence_confirmed` | Отдельные проверки юридической истории и эквивалентности географии; отсутствие подтверждения сохраняется. |
| `geography_basis` | Прямое указание на годовую версию СберИндекса как основание привязки, с ограничением независимого аудита границ. |
| `join_eligible` | Выполнены точные кодовые условия и снят календарный флаг. Этот булев признак не заменяет подтверждение одинаковых границ. |

Шесть календарных решений для среза 2023 касаются `territory_id` 223, 913, 1051, 1068, 1431, 1438. Слой хранит как исходное предупреждение, так и решение. Кодовая связь относится к указанному году: при смене кода прежний код не используется вместо нового только на основании общего `territory_id`.

## Статусы и значения итоговой панели

| Поле / значение | Как читать |
|---|---|
| `fetch_status` | Итог обработки цели: `complete`, `partial_source`, `attribution_review`, `error` или иной явно сохранённый статус отсутствия кода/ответа. |
| `fetch_error` | Причина отклонения или ошибки; пусто при штатной обработке. |
| `source_row_present` | Нужная годовая ячейка присутствует в принятом исходном слое. Она может содержать null. |
| `availability_status` | `observed`, `missing_or_unresolved_source_marker` либо `not_returned`. Отличает число, явный пропуск и отсутствие принятой строки. |
| `value` | Число из принятого источника, сохраняемое независимо от пригодности годовой связи. |
| `analysis_value` | `value`, только если годовая связь допустима и ячейка имеет статус `observed`; иначе null. |
| `analysis_status=observed_conditional_geography` | Число разрешено для анализа с оговоркой о географии источников. |
| `analysis_status=temporal_review` | Календарный вопрос не разрешён. |
| `analysis_status=code_or_boundary_review` | Кодовые условия соединения не выполнены. |
| `cell_coverage.cell_status` | `observed`, `returned_missing` или `not_returned` в поклеточном аудите извлечения. |
| `cell_coverage.expected_by_reference_links` | Нужна ли комбинация даты и исходного кода по годовым связям основной панели. Сам запрос мог включать оба года. |

`complete` означает четыре вернувшиеся ячейки для цели, включая возможные null. `partial_source` означает менее четырёх: корректный ответ за один год сохраняется, даже если второй год под этим кодом отсутствует. Итоговая панель содержит полный ожидаемый набор ключей, поэтому отсутствие ответа не удаляет муниципалитет из знаменателя.

В широком формате `population_total` и `population_urban` получены из `analysis_value`, а `urban_share = population_urban / population_total`. Отношение рассчитывается лишь при обоих наблюдаемых компонентах и положительном общем населении; `urban_share_status=observed_components` обозначает этот случай. Иначе доля пуста со статусом `unavailable`.

## Как использовать слой

Население можно использовать как внешний атрибут в последующей проверке различий потребительских профилей с учётом даты, покрытия и географии. Числа за 1 января не являются среднемесячным населением. Сопоставление двух годовых оценок само по себе не доказывает рост в неизменных границах. Первичные расходы СберИндекса представляют модельную оценку средних безналичных расходов жителей, поэтому умножение их на эту численность без согласования знаменателя не даёт доказанный муниципальный оборот.

Пропуски, ошибки источника и нерешённые подписи нельзя заменять модельным текстом или числом. Обычные нули, явные исходные пропуски и отсутствие строки остаются разными состояниями во всех производных таблицах.
