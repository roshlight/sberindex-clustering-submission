# Историческая география: 78 изменений кода или типа

На 15.09.2026 собран реестр всех **78 муниципальных образований из 17 регионов**, у которых в годовых версиях СберИндекса изменились код или тип между 01.01.2023 и 01.01.2024. Для каждого случая сохранены точные полные коды, официальные наименования, строки исторического ОКТМО, даты и номера изменений. Для трёх случаев прочитаны полные региональные законы. **Эквивалентность границ независимо не подтверждена ни для одного из 78 случаев.** Предыдущие данные и результаты анализа не изменялись.

Главный реестр — [case_register_78.csv](case_register_78.csv). Он соединён по полному 11-значному коду раздела 1 ОКТМО, а затем сверён с годовой пространственной таблицей по `territory_id + snapshot_date`. Названия не используются как ключ. [exact_registry_evidence_156.csv](exact_registry_evidence_156.csv) содержит физическую строку CSV, исходные поля, URL и SHA-256. [region_coverage.csv](region_coverage.csv) показывает распределение случаев и номера изменений по регионам.

Источники кодов — [официальные открытые данные Росстата](https://rosstat.gov.ru/opendata/7708234640-oktmo): версии от 12.01.2023, 19.12.2023 и 25.01.2024. Файл с меткой 01.01.2024 не использован: прежняя проверка установила, что в нём находится более старое содержимое. Дата в имени версии и нынешняя дата распространения файла не доказывают его историческую доступность исследователю в 2023 году. Для текущей описательной проверки это источник истории классификатора, а не журнал публикационных версий статистики.

Во всех трёх законах статья 2 прямо предусматривает объединение перечисленных поселений, статус муниципального округа и правопреемство органов местного самоуправления. Статья 6 устанавливает переходный период до **31.12.2023 включительно**. Статья 8 отсылает к границам по законам 813-ЗРК и 825-ЗРК на 01.01.2023 при осуществлении полномочий в переходный период.

Статья 5 связывает основное вступление в силу с официальным опубликованием и отдельно регулирует часть 2 статьи 4. Первичная запись с датой первоначального опубликования здесь не получена; поэтому точная дата создания оставлена пустой. Дата закона **28.04.2023** не подставлена вместо неё. [reviewed_laws_3.csv](reviewed_laws_3.csv) сохраняет постатейные указатели и границы доказанного. Правопреемство органов и ссылки на прежние границы не заменяют сопоставления полигонов СберИндекса с территорией статистического наблюдения.

## Перекодировка населённых пунктов

На [странице классификаторов Росстата](https://rosstat.gov.ru/classification) загружены таблицы к изменениям ОКТМО **610, 615, 617, 623, 629, 633, 634, 635, 637, 639, 640, 641, 643, 645, 647, 648, 650, 651, 658, 659, 660, 671 / 2023**. Это именно перекодировочные таблицы населённых пунктов; они не представлены как полные тексты поправок.

[settlement_recoding_pairs.csv](settlement_recoding_pairs.csv) сохраняет 10 624 полные пары с номером таблицы и строки Word. Они **не присоединены к муниципальным образованиям по префиксу**: `municipal_territory_id` пуст, статус `not_joined`. Проверка состава населённых пунктов и геометрии остаётся отдельной задачей.

В таблице 671/2023 для Тамбовской области 20 строк содержат «п. 1» — «п. 9» вместо действующего числового кода. Все девять примечаний отсылают к региональным законам. Это не объявлено ошибкой источника и не исправлено по соседним строкам. [recoding_source_review.csv](recoding_source_review.csv) сохраняет исходные подписи и полные примечания со статусом `source_code_requires_review`: для аналитического соединения числовой преемник пока не принят.

## Даты и шесть календарных случаев

В четырёх карточках Росстандарта поля «Дата введения» для изменений 633/2023, 634/2023, 637/2023 и 648/2023 показывают даты 2023 года. У новых кодов из этих изменений в историческом CSV `DateVved=01.01.2024`. [card_registry_date_differences.csv](card_registry_date_differences.csv) сохраняет оба поля; основание их различия здесь не разрешено. Карточки не используются для переноса новых кодов в 2023 год.

Шесть первоначальных календарных флагов экономической панели относятся к **другим** МО: 223, 913, 1051, 1068, 1431, 1438. [calendar_priority_6.csv](calendar_priority_6.csv) повторно проверяет их точные ID, код, дату и SHA прежних первичных материалов. Пять решений основаны на разрешении досрочного применения с 01.01.2023 в карточках изменений; одно — на [официальном уведомлении ФНС для кода 19514000](https://www.nalog.gov.ru/rn35/taxation/submission_statements/rekvizit/12986966/). Они снимают только конфликт даты применения кода. Это не новые доказательства границ и не повод автоматически менять маски ранее выполненного анализа.

## Приоритет продолжения

`P0` в отдельной таблице календарных случаев сохраняет шесть первоначальных флагов для дальнейшей проверки границ. В реестре 78 статус `P1` поставлен трём случаям с уже прочитанным законом, десяти случаям Ставропольского края и Мантурово (`territory_id=2618`), где требуется особенно внимательно проверить смену кода, имени или состава территории. Остальные случаи имеют `P2`. Приоритет отражает порядок дальнейшего аудита, а не оценку величины экономического эффекта.

Для остальных 75 случаев полные региональные законы в этой ограниченной ветке не проверены. Следующий полезный шаг — взять закон из точного номера изменения, установить дату публикации, проверить перечень поселений и границы, затем сопоставить их с исходными полигонами и статистическими территориями. Совпадение названий для такого решения недостаточно.

## Файлы, ограничения загрузки и воспроизведение

[source_catalog.csv](source_catalog.csv) содержит URL, относительный путь, SHA-256 и размер всех 37 принятых источников. Новые байты лежат в `work/data-round2/geography/raw`. Восемь прежних файлов скопированы с проверкой SHA в `work/data-round2/geography/raw/reused`, поэтому прежний архив для воспроизведения не нужен. [manifest.json](manifest.json) фиксирует входные и выходные хеши. [QA.json](QA.json) содержит итог проверок.

В `raw/reused` включены все используемые прежние источники:

- `data-20230112T1301-structure-20260210T1102.csv`;
- `data-20231219T1512-structure-20260210T1102.csv`;
- `data-20240125T1401-structure-20260210T1102.csv`;
- `gost_change_598_2023.html`, `gost_change_594_2022.html`, `gost_change_600_2023.html`, `gost_change_593_2022.html`;
- `fns_19514000_web_tool_text.txt`.

В `work/data-round2/geography/inputs` включены пять входных снимков: `primary_78_code_type_changes.csv`, `sber_yearly_spatial_attributes.csv`, `calendar_code_adjudication.csv`, `registry_vintage_audit.csv` и `round2_geography_reviewed_laws.json`. Их хеши зафиксированы в `manifest.json`. При распаковке общей папки `geography` в другой каталог достаточно заменить её путь в командах ниже; абсолютных путей Windows скрипты не требуют.

Восемь изображений, возвращённых просмотрщиком Росстандарта с HTTP 200, оказались одинаковой заглушкой авторизации. Они исключены из числа документов; обход доступа не выполнялся. Ссылки с параметрами просмотрщика не включены в публичный каталог. Также сохранены неуспешные попытки загрузки: [excluded_retrieval_attempts.json](excluded_retrieval_attempts.json). Проверка TLS не отключалась. Эти отказы не превращены в отсутствие документов вообще.

Переносимый скрипт не обращается к сети и не изменяет входы. Из корня репозитория:

```powershell
uv run --project enrichment --frozen --offline python enrichment/scripts/prepare_round2_geography.py --repo . --raw-dir ../../work/data-round2/geography/raw --historical-raw ../../work/data-round2/geography/raw/reused --inputs-dir ../../work/data-round2/geography/inputs --out ../../work/data-round2/geography/rebuilt
uv run --project enrichment --frozen --offline python enrichment/scripts/verify_round2_geography.py --repo . --report-dir ../../work/data-round2/geography/rebuilt --out ../../work/data-round2/geography/rebuilt/QA.json
uv run --project enrichment --frozen pytest enrichment/tests/test_round2_geography.py -q
```

Команды с `--offline` требуют заранее установленного окружения по `enrichment/uv.lock` или доступного локального кеша пакетов. Сам сборщик не делает сетевых запросов. Ручной разбор трёх законов хранится рядом со скриптом и в снимке входов; сборщик проверяет хеш PDF, прежде чем использовать решения. Исходные документы и их строки сохраняются отдельно от этих решений. Шесть регрессионных тестов, Ruff и 15 проверок готовых таблиц прошли успешно.
