# Аудит трёх новых показателей деятельности

Подготовлена таблица `annual_features.csv` и её копия Parquet: **4032 строки, 2016 МО, 2023–2024 годы**. Ключ — `territory_id, year`. Все 32 колонки исходной годовой панели, порядок строк и флаги `core_eligible`/`conservative_eligible` сохранены. Присоединение выполнено слева по точному ключу; код ОКТМО и дата кодового среза сверены отдельно. Модели не обучались, пропуски не заполнялись, границы не исправлялись.

## Покрытие

Исходная сетка содержит 12 096 позиций: 4032 пары МО/год × 3 показателя. Числовых значений — **10 829**. Нулей и отрицательных значений нет. Из 1267 пропусков 1245 имеют статус `not_returned_or_unaccepted`, ещё 22 — `unresolved_source_marker`. Эти статусы не означают нулевую деятельность и не доказывают статистическое подавление.

Суммарные размеры frozen-выборок — 3973 пары МО/год для core и 3827 для conservative. В whole число исходных значений больше числа признаков: 108 числовых позиций не получают логарифм из-за отсутствующего или неположительного `population_total`. На core и conservative такой разницы нет. Флаг `<prefix>_missing` описывает отсутствие исходного значения; он не заменяет `feature_status` и не является новой маской выборки.

Одновременно доступны три новых признака и все восемь прежних отраслевых долей только в 108 строках core за 2023 год и 105 за 2024 год. Это ограничивает анализ полного пересечения; считать его представительным для всей исходной когорты нельзя. Отраслевые доли A, B, C, D, H, O, P, Q прочитаны из прежней таблицы только для проверки совместного покрытия и не пересчитывались.

Пропуски распределены неравномерно. Например, в 2024 году в Тверской области отсутствуют все 111 позиций трёх показателей для 37 МО, в Самарской — все 108 для 36 МО. Это характеризует полученную выгрузку, а не отсутствие деятельности. По типам МО в 2024 году исходная розница доступна у 225 из 242 внутригородских территорий, 391 из 433 городских округов, 278 из 361 муниципального округа и 854 из 980 муниципальных районов. Полные срезы по региону, типу и заранее заданным диапазонам населения находятся в `coverage_by_*.csv`; признаки исходной панели не использовались для подбора диапазонов по результатам моделей.

## Что означают признаки

| Префикс | Код БДПМО | Период | Исходная величина |
|---|---|---|---|
| `investment` | `8109001` | `17`, значение за год | Инвестиции в основной капитал организаций территории |
| `shipments` | `8401011` | `79`, январь–декабрь | Отгруженные собственные товары, выполненные своими силами работы и услуги |
| `retail` | `8401003` | `79`, январь–декабрь | Оборот розничной торговли |

Все три источника исключают субъекты малого предпринимательства. Выбран итог обследуемых видов деятельности `101`; для инвестиций проверен также итог источников финансирования. Денежные величины сохранены в номинальных тысячах рублей.

Для каждого префикса добавлены:

- `<prefix>_thousand_rubles`: исходное числовое значение без изменения масштаба;
- `<prefix>_missing`: истинно, если это значение отсутствует;
- `<prefix>_log_rubles_per_person`: `log(value * 1000 / population_total)` только при конечных положительных числителе и знаменателе;
- `<prefix>_value_status` и `<prefix>_feature_status`: статус источника и отдельная причина доступности/отсутствия преобразования;
- код источника, годовой кодовый срез, подпись МО, URL региона, SHA256, ключ запроса, номер строки CSV, момент получения и исходный временной флаг.

Знаменатель — frozen `population_total` на 01.01 соответствующего года. Результат описывает **интенсивность деятельности территории по отношению к её населению**, а не доход жителя, производительность работника или индивидуальное потребление. Инвестиции, отгрузка и розница не складываются: их экономический смысл и включение налогов различаются. Общий потребительский ИПЦ здесь не используется как дефлятор инвестиций или выпуска. Содержание показателей разобрано в [первичном пакете](../../data_round3/economy/README.md).

Версия данных получена 16.09.2026. Дата первой публикации и история пересмотров конкретных ячеек неизвестны. Извлечение 2023/2024 значений не доказывает их доступность в соответствующем году. Эти данные пригодны для ретроспективного исследовательского анализа; 2024 год уже просмотрен и не является независимым отложенным тестом.

## Отказы и исторические строки

В журнале сбора 194 успешно разобранных ответа, 12 `response_review` и 7 `form_unavailable`. Последний статус включает непринятые формы из-за дополнительных измерений, конфликтующих подписей или иного представления итога; его нельзя без проверки читать как сетевую недоступность. Ошибки и наборы кодов сохранены в `collection_refusals.csv`. Отдельный список 1267 недоступных позиций с исходными статусами — `unavailable_indicator_rows.csv`.

Равенство источников проверено независимо по ключу `(source_region_url, source_oktmo, year, indicator_id)`: **10 880 разобранных ячеек = 10 851 ячейка с разрешённой годовой связью + 29 без такой связи**. Среди первых 10 829 числовых значений и 22 маркера; все дополнительные 29 строк также содержат маркеры, числовых значений среди них нет.

`historical_source_only_29.csv` сохраняет эти строки и существующие связи того же кода с другим годом только для проверки. Они не перенесены на другой год и не присоединены по названию. Перечень точно совпал с исходным `source_cells_outside_year_link.csv`. Смена кода/типа и неизменный `territory_id` не приняты за независимое доказательство равенства границ: соответствующий флаг остаётся неизвестным, старые календарные и географические ограничения сохранены.

## Файлы и воспроизведение

`coverage.csv` содержит покрытие каждого показателя по году и трём выборкам; `joint_coverage.csv` — пересечение трёх признаков и восьми отраслей. В `missingness_patterns.csv` строковый код состоит из трёх битов в порядке инвестиции, отгрузка, розница: `1` означает доступность. Режим `raw` относится к исходным значениям, `feature` — к логарифмам. При чтении pandas следует задать `dtype={"pattern": str}`, чтобы сохранить ведущие нули.

Из корня репозитория, выбрав новую выходную папку:

```powershell
uv run --frozen python scripts/round3_data_audit.py --self-test
uv run --frozen python scripts/round3_data_audit.py --repo . --out ../../work/round3-analysis/audit-replay-new
uv run --frozen ruff check scripts/round3_data_audit.py
uv run --frozen ruff format --check scripts/round3_data_audit.py
```

Скрипт проверяет уникальность ключей, полное совпадение годовой сетки, кодов, периодов, единиц и статусов. CSV и Parquet источника сверены по всем колонкам; числовой допуск — относительный `1e-12`, абсолютный `0`, с сохранением пропусков. Исходные файлы хешируются до и после работы. Контрактные проверки отдельно отклоняют дубликат ключа, оставляют пропуски для нулевых/отрицательных значений и непригодного населения и проверяют перевод тысяч рублей в рубли.

Повторный запуск дал побайтовое совпадение производных данных и QA. Ruff — PASS. Код и происхождение фиксируют `manifest.json` и `replay_QA.json`. Статус аудита **PASS** означает корректность описанного извлечения и присоединения; он не подтверждает репрезентативность покрытия, причинную связь с потребительскими профилями или эквивалентность муниципальных границ.
