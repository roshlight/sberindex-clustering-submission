# Совместимость переносимого HTML

`report.html` построен из финального `artifact.json` штатным механизмом Data Analytics. Сохранены все 23 блока, 3 графика, 4 таблицы и переход к источникам. Проверка установленного пакета прошла на ширинах **1440 и 390 px**, включая открытие источника с клавиатуры и отсутствие внешних запросов. Канонический payload и сжатый reader runtime не изменялись; их SHA до и после поправки совпадают. Результаты и хэши — в `portable_delivery.json`.

Первоначальная штатная упаковка остановилась на `horizontal_overflow` при 1440 px. Точная проверка тем же Chromium headless-shell показала `clientWidth=1425`, `scrollWidth=1433`: шапка `portable-page-header` имела ширину 1440 px и правую границу 1432,5 px. Причина — `width:100vw` и отрицательные отступы для растяжения шапки до краёв окна. Классическая вертикальная полоса прокрутки занимает 15 px, которые `100vw` всё ещё включает. В современном Chrome с наложенной полосой проблема скрыта. Аналогичный стиль используется у живой шапки `analytics-top-bar`.

Поддержанной настройки ширины шапки в manifest/package_info нет. Пользовательский HTML-блок изолирован в iframe и не может исправить внешний контейнер. Поэтому добавлен один документированный стиль в `<head>` уже собранного штатного документа:

```css
html body .portable-page-header,
html body .analytics-top-bar {
  width: 100%;
  margin-left: 0;
  margin-right: 0;
}
```

Селекторы имеют достаточную специфичность, чтобы загрузка штатных стилей reader позднее не отменила поправку. Она меняет только ширину контейнера и горизонтальные отступы: содержимое не скрывается и не обрезается, графики не перерисовываются альтернативным кодом. Установленный плагин не изменён.

Для воспроизведения из корня репозитория:

```powershell
node scripts/build_round2_portable.mjs --self-test
node scripts/build_round2_portable.mjs `
  --plugin C:/Users/ghora/.codex/plugins/cache/openai-curated-remote/data-analytics/0.2.10-13ceeea1f599 `
  --input reports/round2_analysis/artifact.json `
  --output work/portable-replay/report.html `
  --work-dir work/portable-replay/build
```

`--plugin` должен указывать на установленный пакет; ничего не скачивается. Выходные HTML и receipt должны отсутствовать. Обёртка использует экспортированные `buildPortableArtifact`, `extractPortableChartSvgs` и `verifyPortableArtifact`, сохраняет штатные SVG-варианты графиков и сначала повторяет исходную проверку. Поправка применяется только при `horizontal_overflow`; другие ошибки не обходятся. После неё снова выполняется полная штатная проверка и сравнение с исходным artifact. Успешный HTML появляется только после PASS. Если установленная версия проходит исходную проверку, поправка не добавляется.

`node --check` и четыре встроенные проверки обёртки прошли. Заголовок и начало отчёта визуально проверены на 1440×1000 и 390×844; штатная проверка дополнительно проверяет геометрию всех заявленных блоков и графиков. Технические снимки и ранние неудачные попытки находятся в рабочем каталоге пользователя `work/round2-html-debug/` и `work/round2-html-build/`, вне аналитической поставки. Повторное построение на финальном artifact с абзацем о Зырянке также прошло обе ширины.
