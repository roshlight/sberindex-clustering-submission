# МСП, раунд 6: происхождение географии и дат работников

Получены новые первичные свидетельства о датах работников и проверены встроенные геосправочники автора генератора. **Историческое муниципальное присоединение МСП за 2023–2024 годы пока не обосновано.** В этом раунде нет новых признаков модели, сумм занятости или исправленных муниципальных кодов.

## Что добавлено

Из [отдельного архива работников ФНС от 25.08.2026](https://file.nalog.ru/opendata/7707329152-sshr2019/data-20260825-structure-20200408.zip) извлечён один XML: **900 записей юридических лиц**. У всех `ДатаСост=31.12.2025`, а `ДатаДок=25.08.2026`. Внутри выбранного XML 900 уникальных сочетаний ИНН и даты сведений; 136 значений численности равны нулю, 764 положительны. Пропусков атрибута в этом XML нет. Это результат проверки формата одной выборки, а не оценка заполненности всего реестра.

Полный архив содержит 2 274 члена ZIP и занимает 98 568 936 байт по HTTP-заголовку. Получено 363 780 байт диапазонов; выбранный XML занимает 319 599 байт. Выбор — самый маленький сжатый XML, поэтому он **не репрезентативен**. Проверены SHA полученных байтов, CRC выбранного XML и его точное воспроизведение из сохранённых диапазонов. Полный архив не скачивался; его объявленный сервером SHA не проверен. Полная валидация XML по XSD не выполнялась.

Полученный XML относится к **2025 году**. Он подтверждает различие даты сведений и даты документа в этом выпуске, но не заменяет первичные значения за 2023–2024 годы.

Скачано [сообщение ФНС от 31.03.2023](https://www.nalog.gov.ru/rn77/news/activities_fts/13327467/): для отдельного набора работников описана публикация сведений за предшествующий календарный год, начиная с 1 апреля, с последующими ежемесячными обновлениями. Это историческая документация о расписании публикаций. Она не устанавливает, какие именно редакции данных попали в tochno `v20260605`, и не переносит правило поля `ССЧР` месячного реестра на годовую панель.

## География: теперь доступны сами справочники и проверяемая версия кода

Скачаны метаданные Git, исходник геокодирования, README и авторский текст из [коммита `48a92fa1af335e930f5fb040a7d31a1bf30a44cc`](https://github.com/PavelSyomin/russian-sme-registry/tree/48a92fa1af335e930f5fb040a7d31a1bf30a44cc). Из ранее полученного PyPI-пакета `russian-sme-registry 1.0.0b10` извлечены 12 файлов, включая лицензию, код и пять справочников. Для всех 12 проверено совпадение Git blob SHA с деревом этого коммита. Отдельно скачанный `geocode.py` совпадает с файлом пакета байт в байт. Исходный пакет раунда 5 не изменялся; код автора не устанавливался и не исполнялся.

| Справочник | Строк | Роль в проверенном коде |
|---|---:|---|
| `cities.csv` | 1 117 | Города: адресные компоненты, коды, координаты |
| `cities_additional.csv` | 12 | Дополнительные записи городов |
| `settlements.csv` | 155 921 | Населённые пункты и их справочные атрибуты |
| `regions.csv` | 86 | Нормализация названий и кодов регионов |
| `abbr.csv` | 393 | Типы и сокращения адресных объектов |

В [README автора](https://github.com/PavelSyomin/russian-sme-registry/blob/48a92fa1af335e930f5fb040a7d31a1bf30a44cc/README.md) заявлено использование географии 2021 года и справочников конца 2021 — начала 2022 года независимо от года генерируемой строки. Это утверждение автора; фактическая дата действия каждой записи справочника отдельно не установлена. Во всех пяти CSV отсутствуют поля `start_date`, `end_date`, `valid_from`, `valid_to`. Поле `foundation_year` в городском справочнике описывает основание города и не считается периодом действия соответствия адреса и кода.

В проверенном коде есть два маршрута: локальные справочники и DaData. У обоих адресный контракт содержит восемь полей региона, района, города и населённого пункта; год или дата действия адреса в этот список не входят. В локальном маршруте исходные адресные поля затем удаляются. Альтернативный маршрут берёт первое предложение DaData. В этом раунде запросы в DaData не выполнялись. **Маршрут, параметры запуска и точный набор исходников сборки tochno не установлены.** Совпадение PyPI-пакета с Git-коммитом не доказывает происхождение конкретной публикации данных.

В `cities.csv` для Москвы, Санкт-Петербурга и Севастополя сохранены группировочные коды `45000000`, `40000000`, `67000000`. Это подтверждённое свойство одного справочника генератора, а не доказательство причины каждой группировочной строки в файлах tochno. Отдельные внутригородские записи присутствуют в дополнительном справочнике; они не дают автоматического разбиения всех организаций по внутригородским муниципалитетам.

## Проверка записи кодов

Коды прочитаны как текст. Пустая ячейка, научная запись и строка иной длины не превращались в ноль, не дополнялись нулями и не использовались как муниципальный ключ.

| Справочник | Ровно 8 или 11 цифр | Другая длина цифровой строки | Научная запись | Иной синтаксис | Пусто |
|---|---:|---:|---:|---:|---:|
| `cities.csv` | 1 018 | 99 | 0 | 0 | 0 |
| `cities_additional.csv` | 11 | 0 | 0 | 0 | 1 |
| `settlements.csv` | 148 295 | 7 229 | 396 | 1 | 0 |

Это классификация исходных строк кода, а не оценка числа неверно геокодированных предприятий. Даже 8 или 11 цифр не доказывают существование кода в нужную дату. Авторский алгоритм также исключает неоднозначные ключи справочника на каждом варианте сопоставления: наличие повторов в сыром справочнике само по себе не означает ошибочного принятого соединения.

## Работники: учитывать редакцию, а не только год

В прочитанном коде отдельные сведения работников упорядочиваются по убыванию `doc_date` внутри сочетания `tin/data_date`. Выбирается первая запись, а год строится из `data_date`; затем данные присоединяются к панели по `tax_number/year`. Следовательно, для воспроизведения значений нужны также использованные редакции исходных архивов. Одного года недостаточно, чтобы доказать доступность значения в исторический момент прогноза. Это вывод о коде, а не подтверждение запуска данного алгоритма при публикации tochno.

В README отдельный набор работников описан для юридических лиц. Отсутствие работников у ИП в прежних файлах tochno нельзя заменять нулём. Здесь значения работников не суммируются; новые сведения не снимают ограничений, выявленных в пятом анализе.

## Что осталось недоступно

Три адресные проверки исторических ZIP вернули HTTP 404: предполагаемые выпуски `20240401`, `20241225`, `20250401`. Для `20241225` ссылка дополнительно обнаружена в сохранённом автором тестовом HTML паспорта; для двух апрельских URL использован явно обозначенный шаблон имени и документированное расписание, а не найденная действующая ссылка. Это ограниченные попытки, не доказательство отсутствия всех исторических архивов.

Журнальный [PDF автора](https://press.psu.ru/index.php/geogr/article/download/9926/6220/22969) найден в поиске, но локальная загрузка по HTTPS завершилась ошибкой TLS, по HTTP — пустым ответом. PDF не включён в пакет и не используется как проверенный локальный источник. GitHub API списка issues вернул 403; найденная задача № 6 не содержала тела или комментариев с доступной резервной копией. Поисковые запросы, происхождение предполагаемых ссылок и неудачные попытки сохранены в `search_ledger.json` и HTTP-метаданных сырого пакета.

Дальнейший сбор должен получить исходные отдельные архивы работников за 2023 и 2024 годы вместе с датами редакций, а также сведения о фактическом запуске генератора tochno: версию, маршрут геокодирования, справочники и исходные адресные записи. Для исторического муниципального соединения дополнительно нужны датированное соответствие адреса и территории и проверка границ. Пока статус — **ready with conditions** для проверки происхождения источников, `historical_municipal_join_approved=false`, `model_adoption=false`.

## Воспроизведение

Команды выполняются из корня репозитория. Зависимости закреплены в `enrichment/uv.lock`.

```powershell
# Повторное извлечение и фиксация пакета из уже сохранённых источников.
uv run --project enrichment --frozen --offline python enrichment/scripts/collect_round6_sme.py --raw ../../work/data-round6/sme --prior-raw ../../work/data-round5/sme --offline

# Полностью автономный аудит: каталог вывода должен быть новым.
uv run --project enrichment --frozen --offline python enrichment/scripts/audit_round6_sme.py --raw ../../work/data-round6/sme --out work/round6-sme-replay

uv run --project enrichment --frozen --offline pytest enrichment/tests/test_round6_sme.py -q
uv run --project enrichment --frozen --offline ruff check enrichment/scripts/collect_round6_sme.py enrichment/scripts/audit_round6_sme.py enrichment/tests/test_round6_sme.py
```

Для аудита нужен только самодостаточный сырой пакет раунда 6: `SOURCE_MANIFEST.json` проверяет все файлы до вычислений. Предыдущий пакет требуется только коллектору, который переносит проверенные файлы автора; аудит не обращается к нему и к сети. Для нового сетевого получения используют новый каталог и команду коллектора без `--offline`; сохранённые неудачные попытки не перезаписываются автоматически. Текущий коллектор закрепляет конкретный наблюдённый выпуск ФНС от 25.08.2026, а не выбирает будущий выпуск молча.

Аудит создаёт десять CSV, `QA.json` и `manifest.json`. Манифест содержит SHA входного инвентаря, кода, lockfile и машинных результатов. README и `evidence_matrix.csv` составлены отдельно. У первых пробных HTTP Range сохранён серверный заголовок `Date`, но не локальное время начала запроса; это прямо отмечено в поисковом журнале. Дата HTTP-ответа не используется как дата публикации данных.

Проверены 18 содержательных тестов и Ruff. Тесты различают даты сведений и документа, ноль, пропуск и отрицательное значение, сохраняют научную запись кодов, блокируют изменение или добавление сырого файла и изменение временного контракта адресов. `QA.json=PASS` относится к указанным проверкам пакета, а не к разрешению использовать МСП в модели.
