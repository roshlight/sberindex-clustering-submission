# Что изменилось в данных четвёртого аналитического раунда

Восстановлены **779 денежных значений**, которые добавляют **770 допустимых логарифмических признаков**. Изменения затрагивают **445 строк МО × год и 223 разных МО**. Все прежние **10 829** чисел, их исходные реквизиты и **4032** годовых ключа сохранены. Статус данных: **ready with conditions** для ретроспективного описательного анализа при сохранении прежних ограничений.

Задача аудита — подготовить сопоставимые признаки для проверки экономической интерпретации муниципальных потребительских профилей. Единица наблюдения — МО × год, годы — 2023 и 2024, исходная совокупность — 2016 МО. Здесь не обучаются модели и не оценивается предсказание будущего: сведения выгружены в 2026 году, даты их первого опубликования и история пересмотров неизвестны.

Под полным набором здесь понимаются три конечных логарифма `log(value*1000/population_total)`. Числовое значение допустимо для логарифма только при положительных сумме и численности населения. Новые значения у Рязани, Касимова и Скопина за 2023 год дают по одной ячейке без пригодного знаменателя. Вышневолоцкий городской округ (`territory_id=2710`) даёт ещё по три в каждом году. Все пять строк находятся вне `core`; численность населения не заполнялась предположениями.

Прирост распределён по 11 регионам. На Тверскую и Самарскую области приходится **432 из 779 ячеек (55.46%)**. Это следствие исправления региональных способов извлечения данных. Улучшение покрытия нельзя считать случайной подвыборкой российских муниципалитетов. Полные таблицы с явными знаменателями: `gain_by_region.csv`, `gain_by_population.csv`, `gain_by_type.csv`, `gain_by_restrictions.csv`.

В кандидате остаются **488 пропусков**: **464** `not_returned_or_unaccepted` и **24** `unresolved_source_marker`. По показателям это **17** инвестиций, **117** отгрузки и **354** розницы. Их причины не подменяются нулевой экономической активностью или конфиденциальностью. Числовых нулей и отрицательных значений в принятом снимке нет. Вне принятой связи кода с годом остаются **24** вновь разобранные пустые ячейки; они не включены в признаки. Прежние исходные ячейки вне годовой связи остаются в третьем раунде без изменений.

`annual_features.csv` и `.parquet` сохраняют схему предыдущего набора в начале таблицы; новые колонки добавлены справа. `old_*` хранят прежние суммы, логарифмы и доступность. Поля `activity_new_numeric_count`, `activity_new_feature_count` и соответствующие флаги показывают, какие ячейки действительно добавлены. `activity_all3_features_common` обозначает полный набор во всех трёх атрибутах в обеих версиях данных. `core_common_activity_complete` и `conservative_common_activity_complete` — пересечения с прежними масками, пригодные для проверки чувствительности к покрытию, но не новая основная совокупность.

Все собственные денежные признаки МО на `common` остались одинаковыми. При обучении модели только на неизменной `common` выборке и прочих одинаковых входах old/new сравнение дублирует одну задачу. Сравнение прогнозов моделей, обученных на полных фиксированных выборках old/new, на этой подвыборке может отражать изменение обучения за счёт остальных МО. Для проверки полезности дополнения следует также отдельно читать результаты на `newly_complete` и прочих затронутых строках, сохраняя первоначальные folds и базовые признаки.

Маски `core_eligible`, `conservative_eligible`, `code_type_changed` и `calendar_review` совпадают с прежними побитно. Ограничения для **78** МО с изменениями кода/типа и **6** календарных случаев сохранены. Левые соединения проверяются по точным годовым ключам, единицам, периодам и виду деятельности. Сопоставимость юридических границ не установлена. Общая сумма инвестиций, отгрузки и розницы не строится: это разные показатели, охватывающие организации без малого предпринимательства; интенсивность на жителя не является доходом жителей.

Сохранность прежних чисел в кандидате не доказывает отсутствие пересмотра источником: старые числовые ячейки не были запрошены повторно. Все **779** дополнений сверены с таблицей восстановленных ячеек и хешами исходных ответов. Проверка исходного парсинга на всех **805** вновь разобранных ячейках выполнена отдельно в `reports/data_round4/economy/independent_QA.json`. Этот аудит повторно проверяет использование принятого снимка и воспроизводит прежний набор признаков, но не считает такую реконструкцию независимой проверкой первичных ответов.

Для повторения из корня репозитория используйте новый пустой каталог результата:

```powershell

uv run --frozen pytest tests/test_round4_data_audit.py

```

`manifest.json` содержит хеши входов, скрипта, неизменённого помощника третьего раунда, lockfile и 21 выходного файла. `QA.json` фиксирует численную сверку. `replay_QA.json` отдельно фиксирует повторение артефактов, проверки кода и тестов. Файлы прошлых раундов не изменены; текущий отчёт не утверждает улучшения качества модели.
