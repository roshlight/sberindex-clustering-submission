# Поиск и обогащение данных для первого кейса

Этот модуль ищет недостающие определения и внешние данные, сохраняет первоисточники и готовит проверяемые таблицы. Он работает отдельно от первой версии эксперимента: её код, зависимости и результаты не меняются.

Начать с [продолжения сбора населения и проверки кодов](../reports/enrichment_v2/REPORT.md). Первый этап сохранён в [enrichment_v1](../reports/enrichment_v1/REPORT.md); исходные приоритеты — в [плане](../docs/data_enrichment_plan.md) и [каталоге источников](../docs/source_catalog.md).

```mermaid
flowchart LR
    A[Потребности и известные данные] --> B[План запросов]
    B --> C[SearXNG на сервере]
    C --> D[Кандидаты и ссылки первоисточников]
    D --> E[Загрузка, хеши и разбор]
    E --> F[OpenRouter: извлечение с цитатами]
    F --> G[Проверка цитат и сопоставление источников]
    E --> H[Парсеры таблиц]
    H --> I[Проверка кодов, дат и покрытия]
    G --> J[Реестр свидетельств и открытых вопросов]
    I --> J
```

## Установка

Нужны Python 3.12 и `uv`. Выполнить из этой директории:

```bash
uv sync --frozen
uv run --frozen pytest -q
uv run --frozen ruff check .
uv run --frozen ruff format --check .
```

Сервер использует уже установленный SearXNG. Ключ OpenRouter читается из существующего защищённого файла; передавать его в командной строке или записывать в репозиторий не нужно. В окружении задаются `SEARXNG_URL` и `OPENROUTER_API_KEY_FILE`. Пример без секретов: [.env.example](.env.example).

## Полный поиск

Для текущего сервера сначала открыть SSH и загрузить его уже настроенное окружение:

```bash
ssh timeweb-server
cd /home/vpnadmin/services/sberindex-enrichment/enrichment
set -a
. ../runtime.env
set +a
export PATH="$HOME/.local/bin:$PATH"
```

Затем выполнить команду ниже с новым именем каталога запуска:

```bash
uv run --frozen sber-enrich \
  --needs ../configs/data_needs.json \
  --catalog ../configs/source_catalog.json \
  --run-dir runs/research-YYYYMMDD-01 \
  --expand-queries --engines "google cse" \
  --pages 2 --max-queries 100 --max-documents 96 --max-linked 24 \
  --search-interval 2 \
  --llm-documents 48 --search-workers 2 --fetch-workers 3 --llm-workers 3
```

Это ограниченный запуск. Постоянного фонового опроса, расписания и бесконечного расходования токенов нет. Флаги задают верхние пределы; фактический объём зависит от выдачи и доступности источников. Поиск исключает уже имеющиеся наборы и отложенные потребности P2. Дополнительные ссылки скачиваются на один переход от проверенных страниц первоисточников.

Имена моделей проверяются по текущему каталогу OpenRouter. С 15.09.2026 по запросу пользователя все новые модельные этапы по умолчанию используют `deepseek/deepseek-v4-pro-0813`: извлечение определений, расширение запросов и сопоставление свидетельств. Ответы проходят проверку JSON Schema. Поддержка цитаты проверяется по сохранённому тексту. Это проверка происхождения фрагмента, а не доказательство правильности экономического вывода. Исторические запуски сохраняют первоначальные модели в своих манифестах.

Модели видят публичные документы и постановку исследования. Им не передаются ключи, частные сообщения группы или внутренние документы других проектов. Они не дополняют пропуски населения и зарплаты, не создают территориальные коды и не принимают решения о соединении числовых таблиц.

## Повторный запуск и журнал

Каждый запуск получает отдельную директорию. `--resume` допускается только при тех же входных файлах, коде, зависимостях, адресе поиска и параметрах. Успешные запросы к моделям повторно не оплачиваются: результат берётся из локального кэша. Неопределённый исход или неудачная генерация требует осмотра записи и явного решения о новом запуске. Каталог с ошибкой не следует удалять ради автоматического повтора.

`run_manifest.json` хранит параметры, хеши и итог; `events.jsonl` — этапы; `search/` — запросы и выдачу; `document_inventory.json` — доступность и хеши; `raw/` и `text/` — исходные материалы; `model_calls/` — результаты и происхождение вызовов; `cards/` — проверенные фрагменты; `router_attempts.json` — каждую HTTP-попытку и сообщённый расход. Журнал обновляется атомарно по ходу запросов. Один процесс владеет одним каталогом запуска.

Ответ HTTP 200 от SearXNG может содержать ошибки поисковых движков. Такие ответы учитываются отдельно. Пустая выдача, блокировка, недоступный файл или неизвестная стоимость остаются явными статусами. При аварийном завершении генерации итоговая стоимость может быть неизвестна; журнал не подменяет расчёт OpenRouter.

Полные страницы, цитаты и рабочие журналы остаются на сервере. Для репозитория готовится отдельный проверенный пакет: краткий отчёт, реестр URL и хешей, принятые числовые слои, QA и открытые вопросы.

## Числовые слои

Для повторного запуска на этом сервере настроен `PUBLIC_CA_BUNDLES_JSON`: карта точных доменов и публичных PEM-файлов. Она относится только к загрузчику источников. Происхождение сертификатов, проверка TLS, ограниченная распаковка gzip и совместимость двух PDF с ошибочным `aws-chunked` описаны в [контракте соединений](../docs/enrichment_connectors.md). Глобальное хранилище доверия сервера не менялось.

При исчерпании лимита OpenRouter можно выполнять поиск и числовые парсеры с `--llm-documents 0`, без `--expand-queries`. Отказы доступа останавливают очередь генераций, а не удаляют уже загруженные источники. Перед новым этапом владелец снял прежний денежный лимит; API подтвердил `limit=null`. Это состояние доступа на момент проверки, а не обещание неограниченной доступности сервиса. Для карточек установлен предел ответа 16000 токенов после наблюдавшихся обрезанных генераций; автоматического повторного списания за них нет.

- `../scripts/prepare_municipal_crosswalk.py` готовит версионное соответствие `territory_id → ОКТМО`, проверяет уникальность внутри даты и покрытие панели. [Аудит](../docs/source_catalog.md).
- `scripts/prepare_population.py` извлекает исходные ячейки двух бюллетеней Росстата, сохраняет уровни строк и QA. [Аудит населения](../docs/population_source_audit.md). Суммировать все уровни таблицы нельзя. ТЕРСОН-МО не переименовывается в ОКТМО.
- `scripts/prepare_bdpmo_population.py` получает точные значения регионального интерфейса: доступны `--limit`, `--interval`, `--ca-bundle`, отдельный кэш и журнал запросов. `scripts/prepare_population_code_bridge.py` проверяет официальное соответствие кодов и присоединяет проверочный набор. [Контракт и команды](../docs/population_join_followup.md).
- `scripts/prepare_core_context.py` собирает контекст основной панели за 2024 год с сохранением пропусков доступности. [Команда и QA](../docs/core_context.md).

Новый признак считается пригодным для анализа после проверки ключа, даты, единиц и покрытия. Годовой показатель остаётся годовым при соединении с месячной панелью. Никакие новые данные не превращают уже просмотренный 2024 год в независимый тест новых гипотез.

## Массовое население: сбор и проверка

Для нового сбора используется `scripts/run_population_bulk.py`. Он получает точные коды из годовых связей, проверяет их присутствие в региональной форме и сохраняет каждый обработанный муниципалитет отдельным checkpoint. Групповые ответы допускаются только при однозначном соответствии полных подписей кодам в той же форме. Неизвестные форматы и противоречия остаются отдельными статусами.

`complete` в журнале загрузки означает, что источник вернул четыре запрошенные ячейки; среди них могут быть пропуски. Покрытие измеряется по фактическим числам в `cell_coverage.csv` и итоговом отчёте. Пропущенное городское население не принимается за ноль.

`scripts/verify_population_bulk.py` сверяет выгрузку с сохранёнными ответами: хеши, параметры запроса, строку CSV, колонку года и исходное значение. `scripts/prepare_population_panel.py` строит полную сетку основной выборки, проверяет код, дату, единицы, уникальность и статус загрузки. Неизвестные или отвергнутые значения не попадают в `analysis_value`. Доля городского населения рассчитывается только при двух наблюдаемых компонентах и положительном общем населении.

Для календарных вопросов применяется отдельный журнал `calendar_code_adjudication.csv`: исходные предупреждения сохраняются, решение проверяется по точному сочетанию муниципалитета, даты и восьмизначного кода, а копии источников — по SHA256. Разрешение вопроса о дате кода не объявляет доказанной эквивалентность границ.

Конкретные каталоги канонического запуска, команды повторной сборки и правила чтения столбцов приведены в [инструкции поставки v2](../reports/enrichment_v2/REPRODUCE.md). Для новой версии парсера создаётся новый выходной каталог; старые сырые ответы сохраняются.
