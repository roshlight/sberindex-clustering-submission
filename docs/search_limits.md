# Ограничения поисковых запросов

Один экземпляр `SearchGuard` используется всеми поисковыми потоками одного запуска: по умолчанию он допускает новый вызов не чаще одного раза в 2 секунды и после двух ответов с `too many`, `429` или `Suspended` в `unresponsive_engines` откладывает остальные вызовы через `SearchDeferred`. Несколько проблемных движков в одном ответе считаются одной ошибкой ограничения частоты; успешный ответ счётчик не обнуляет. Исключение с явным HTTP-статусом 429 также учитывается и передаётся вызывающему коду без повторной попытки. Ожидание и HTTP не удерживают общую блокировку; уже допущенные запросы могут завершиться, а ожидающие повторно проверяют состояние перед запуском. Guard возвращает исходный результат без изменений: частичный ответ не становится полным, отсутствие результатов не означает отсутствия источников. Автоматических повторов и автоматического сброса нет. Отложенные запросы следует повторять после паузы отдельным ограниченным запуском с новым экземпляром guard, сохраняя их прежний статус; параллельно использовать прямые официальные источники и обычный веб-поиск. Интервал 2 секунды — локальное ограничение нагрузки, а не подтверждённая квота или гарантия доступности SearXNG и его поисковых движков.
