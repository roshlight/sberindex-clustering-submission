## Извлечение и результат

Код: `enrichment/src/sber_enrichment/bdpmo.py`; запуск: `enrichment/scripts/prepare_bdpmo_population.py`. Первый POST выбирает `pl=8112027`. Второй выбирает ровно один код из официального массива `p_oktmo`, годы `2023,2024`, период `208` с подписью «на 1 января», виды населения `11,12` и формат CSV. CSV содержит подписи, поэтому связь чисел с кодом устанавливается точным единственным кодом запроса; внешнего соединения по названиям нет.

| Балашиха | `46704000` / `46704000` / `46704000000` | 549846 | 526851 | 554248 | 530311 |
| Краснодар | `3701000` / `03701000` / `03701000000` | 1226226 | 1121291 | 1243839 | 1138654 |

Все величины — человек на 1 января указанного года. Успешный исходный пакет: `enrichment/data/bdpmo-pilot-20260914-v2/`, 12 наблюдений. Присоединённый пакет: `enrichment/data/bdpmo-linked-pilot-20260914-v1/`, таблицы CSV/Parquet и manifest. `territory_id` соответственно 1, 1439, 622. Для каждого года взят соответствующий срез справочника СберИндекса; у этих трёх МО коды между 2023 и 2024 совпадают. Историческая редакция Росстата подтверждает структуру и точные коды; это не утверждение, что вся геометрия территории независимо проверена.

В Подмосковье источник разделил годы на два блока с разными групповыми подписями. Парсер сохраняет `source_section`, читает даты из каждого заголовка и требует четыре уникальных сочетания даты и вида населения. Неизвестная раскладка или повтор не превращаются в результат. Прочерк и пустота остаются пропуском; легенда другого статистического продукта не используется. Городское население не может превышать общее.

Пакет v1 оставлен со статусом `partial`: первый запрос Майкопа завершился таймаутом, а раздельная раскладка Подмосковья ещё не поддерживалась. После доработки v2 завершился успешно. Запросы, ответы, время получения и хеши находятся в `work/population-join-probes/bdpmo-cache/`. Дата первичной публикации не установлена: `published_at=null`. Это редакция, полученная 14.09.2026, а не доказательство доступности тех же величин в 2023 году.

## Почему приняты именно эти коды

Схема Росстата задаёт `TER` длины 2, `KOD1`, `KOD2`, `KOD3` длины 3 и `RAZDEL`. В скачанном историческом файле 200487 строк; раздел 1 содержит 24848 строк, во всех `KOD3=000`, комбинации `TER+KOD1+KOD2` уникальны. Код СберИндекса проверялся точным совпадением всех четырёх частей с этим разделом. Только после этого первые три официальных поля дают восьмизначный код МО. Для Краснодара точный код формы `3701000` численно равен единственному подтверждённому `03701000`; оба представления сохранены. Это проверка официальных полей, а не угадывание кода по названию или примерам.

Для основной панели из 2016 МО срез СберИндекса 2024 дал **1627 точных совпадений**, **389 отсутствий** в выбранной исторической версии ОКТМО. Это охват справочником, не охват населением. Все 389 ID сохранены в `primary_unmatched_2024.csv`. Причина каждого отсутствия ещё не установлена; различия дат вступления изменений требуют проверки. Замена версии на последнюю ради увеличения охвата не выполнена.

Подготовлены 1627 запросов-кандидатов в `primary_population_candidate_targets.json`. Их коды получены из подтверждённых полей, региональные адреса существуют в официальном перечне. Каждый код ещё обязан точно присутствовать в форме БДПМО перед загрузкой; иначе адаптер отклонит запрос. Результаты массового запуска останутся неприсоединёнными до проверки среза соответствующего года и территориального контура. В частности, список из среза 2024 не разрешает автоматически присоединить население 2023 после изменения кода.

CLI поддерживает `--limit` и `--interval` (секунды между сетевыми запросами), последовательную загрузку, повторное использование проверенного кэша и отказ от перезаписи папки результата. Например, из каталога `enrichment`:

```powershell
uv run --frozen python scripts/prepare_bdpmo_population.py --targets data/bdpmo-linked-pilot-20260914-v1/primary_population_candidate_targets.json --output data/bdpmo-next-batch --cache ../../../work/population-join-probes/bdpmo-cache --limit 10 --interval 1
```

Эта команда приведена для следующего ограниченного запуска и здесь не выполнялась. В фактически просмотренном меню экспорта есть Excel и CSV; XML нет. Упоминание XML в старом конференционном сборнике не подтверждает его поддержку этим экземпляром БДПМО.

## Воспроизводимое присоединение и проверка сервера

Кодовое присоединение теперь выполняет отдельный CLI `enrichment/scripts/prepare_population_code_bridge.py`. Он принимает пути к историческому CSV ОКТМО, двум срезам СберИндекса, `assignments.parquet`, исходному CSV населения, HTML-перечню региональных баз и новой папке результата. Сеть этот скрипт не использует. Повторный фактический запуск создал `enrichment/data/bdpmo-code-bridge-20260914-v2/` и воспроизвёл 1627 кандидатов, 389 неприсоединённых ID и 12 присоединённых ячеек. Manifest содержит хеш скрипта и всех входов. Для передачи воспроизводимого результата используется этот пакет.

Поле `in_primary_cohort` уточняет охват пилота: Майкоп и Балашиха входят в основную панель; Краснодар не входит. Три МО выбирались для проверки региональных интерфейсов. Поэтому 12 ячеек пилота нельзя называть населением трёх МО основной панели. Это уточнение не меняет рассчитанный по 2016 ID охват справочника.

На сервере 14.09.2026 выполнен новый пилот с отдельными кэшем и результатом: `/home/vpnadmin/services/sberindex-enrichment/enrichment/data/bdpmo-server-pilot-20260914-v1/`. Статус `complete_unlinked`, 3 успешных муниципалитета, 12 ячеек. Все 12 значений совпали с локальным источниковым пилотом. Хеши выходов и девяти сырых GET/POST-ответов проверены. Локальная копия результата находится в `enrichment/data/bdpmo-server-pilot-20260914-v1/`.

Для Linux добавлен `BdpmoClient(ca_bundle=...)` и аргумент `--ca-bundle`. Публичный PEM дополняет системный SSL-контекст через `load_verify_locations`; проверка TLS остаётся включённой.
