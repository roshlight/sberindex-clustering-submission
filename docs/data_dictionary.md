# Данные и определения профилей

Основной источник — [оригинальный архив СберИндекса](https://www.sberbank.com/common/img/uploaded/files/pdf/sberindex/hackathonlicence.zip), опубликованный на [странице Data → Sense](https://sberindex.ru/ru/research/data-sense-opisanie-nabora-dannikh-khakatona-sberindeksa-po-munitsipalnim-dannim). В проекте используется `consumption.parquet`. Исходные данные загружены 14.09.2026; SHA-256 файла: `9833ddaaee7b2a182ed4cceeed16469031700ea87d508bd976150c6770ef8a61`.

Это оценка средних месячных безналичных расходов жителей муниципального образования на основе моделей СберИндекса. Она не равна обороту предприятий муниципалитета. Формулы статистических весов, численность знаменателей категориальных средних и точный порог качества в просмотренном описании не раскрыты. Дополнительно делить показатель на население нельзя.

| Поле | Тип после загрузки | Определение |
|---|---|---|
| `date` | строка `YYYY-MM` | Месяц наблюдения |
| `territory_id` | int64 | Идентификатор муниципалитета в постоянных границах |
| `category` | строка | Одна из шести опубликованных категорий |
| `value` | float64 | Модельная оценка средних расходов жителей за месяц, руб. |

Фактический исходный Parquet использует `territory_id` int16 и `value` int32. Загрузчик расширяет типы без изменения значений. PDF описания называет числовой столбец `consumption`, фактическое имя — `value`. Сохранённый технический индекс pandas не используется. Ключ наблюдения: `(territory_id, date, category)`.

## Основной профиль

Для каждого муниципалитета и месяца используются пять опубликованных средних `x_j`. Вектор признаков имеет компоненты:

`P_j = x_j / sum(x_1, ..., x_5)`.

Это нормированный профиль пяти опубликованных средних. Его компоненты суммируются к единице по определению, но не называются долями потребительского бюджета: общий статистический знаменатель категорий пока не подтверждён. «Все категории» не входит в этот вектор и не используется в его знаменателе. Показатель «Прочее» также не входит в основную спецификацию.

Для проверки чувствительности предусмотрены два явных изменения:

- `drop_category`: исключение одной опубликованной категории с повторной нормировкой оставшихся средних;
- `include_residual=True`: добавление `Прочее (арифметический остаток) = Все категории − сумма пяти средних`, затем нормировка выбранных компонентов. Остаток всегда вычисляется по всем пяти исходным средним до `drop_category`. Это арифметическая чувствительность, а не подтверждённая шестая категория бюджета.

В оригинальном наборе остаток строго положителен во всех 50 521 муниципалитетах-месяцах. Это подтверждает арифметическую согласованность, но не заменяет проверку общности знаменателей и отсутствия пересечений категорий. Если при расчёте чувствительности остаток неположителен, функция завершает работу с ошибкой.

## Календарь, идентификаторы и проверки

Проверенный набор содержит 303 126 строк, 2 190 территорий, шесть категорий и 24 месяца: январь 2023 — декабрь 2024. Все 50 521 наблюдаемые пары МО–месяц содержат шесть категорий. Повторов ключа, null, нулевых и отрицательных расходов нет. Полную историю имеют 2 016 территорий; 174 имеют неполную. У 78 территорий обнаружены внутренние пропуски, суммарно 498 МО–месяцев. Отсутствие месяца не означает нулевых расходов.

`load_panel(path, complete_only=True)` проверяет ожидаемый календарь 2023–2024 и сохраняет только территории с каждым из 24 месяцев. `complete_only=False` сохраняет все наблюдаемые МО–месяцы. В обоих режимах неполный набор категорий в существующем МО–месяце, повтор ключа, null и неположительные расходы вызывают ошибку. Необязательный `expected_periods` позволяет явно задать другой проверяемый календарь, например для синтетических тестов. Данные никогда не дополняются нулями и не дедуплицируются автоматически.

`make_profiles` возвращает словарь `месяц → (IDs, P, categories)`. Месяцы и коды территорий отсортированы; столбцы основного профиля следуют порядку таблицы пяти категорий выше. При неполной входной панели набор IDs может отличаться между месяцами; сопоставлять строки разных месяцев по позиции нельзя.

Портальная CSV-выгрузка заменяет коды названиями: 2 190 кодов имеют 2 118 уникальных названий, а 49 названий соответствуют нескольким территориям. Поэтому название не является ключом. Кодовый оригинал полностью сверяется с портальным экспортом после проекции на названия, значения, категории и даты: все 303 126 строк совпадают как мультимножество. Эта сверка подтверждает согласованность экспортов одного источника, а не независимую точность его экономических оценок.

`municipality-codebook.csv` содержит `code,name`; связь с `territory_id` проверена без потерь и размножения строк. Названия предназначены для подписей. География, регион, ОКТМО и другие внешние атрибуты в этот модуль не включены.

## Локальная подготовка

Скрипт ничего не загружает из сети. `--source-dir` указывает на локальный каталог ранее собранных источников. В нём нужны исходный `hackathonlicence.zip` либо `hackathon-bundle/hackathonlicence/consumption.parquet`, а также `municipality-codebook.csv`, `municipal-spending-metadata-decoded.json` и `bundle-data-audit.json`.

```bash
python scripts/prepare_data.py --source-dir /path/to/sberindex-research --output-dir data/raw
```

Скрипт сверяет SHA-256 потребления с сохранённым аудитом и копирует только четыре входа: `consumption.parquet`, `municipality-codebook.csv`, `dataset_metadata.json`, `source_audit.json`. `manifest.json` фиксирует их хеши, размеры, официальные URL и дату получения источников. Байты входов сохраняются без изменений. Повторный запуск с теми же источниками ничего не меняет; отличающиеся существующие файлы не перезаписываются. Копирование транспортных связей, market access и других исходников не выполняется. Настройка исключения `data/` из Git находится вне обязанностей этого скрипта.
